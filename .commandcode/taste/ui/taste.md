# UI / design preferences

- Wants skeleton or spinner loading states instead of plain "Loading…" text; calls out visible text-only loading as a defect. Confidence: 0.85
- Cares about animation smoothness — no jitter, flash, or abrupt reflow when a record is added or a list refreshes; expects transitions to feel smooth site-wide. Confidence: 0.8
- Objects strongly to flat/monochrome palettes, cramped layouts, and weak contrast; wants generous, deliberate pixel-level spacing tuned per page (evaluates like a very picky senior designer). Confidence: 0.8
- Prioritizes the mobile experience — asks for each page to be reviewed and rebuilt with the phone as the primary target rather than desktop-first. Confidence: 0.75
- When existing UI styling is bad, prefers a ground-up rebuild (including CSS from scratch) over incremental patching of what's there. Confidence: 0.75
- Expects list views (journal / recent activity) to be exhaustively browsable with pagination or "load more" instead of silently truncated lists. Confidence: 0.7
- Uses visual evidence (screenshots) to judge UI and expects the assistant to look at the rendered pages, not just the code. Confidence: 0.6
- Before any new UI gets implemented, wants to see a static HTML mockup/preview first (pushed to the visual companion browser view) and approve or pick between layout options. Confidence: 0.85
- Expects one-time guided flows (tours, onboarding) to stay re-runnable: wants a replay entry in the app's settings/preferences ("in the settings I can re-run it right") rather than being strictly show-once with no way back. Confidence: 0.7
