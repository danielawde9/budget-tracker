No existing migration file was edited. The added JSON key is:

```sql
'linkedEventId', (select oe.linked_event_id::text
  from public.occurrence_events oe
  join public.financial_events fe on fe.id = oe.linked_event_id
  where oe.occurrence_id = funded.id and oe.action in ('link','confirm')
    and fe.effective_date <= v_as_of
    and not exists (
      select 1 from public.financial_events rev
      where rev.reversal_of = oe.linked_event_id and rev.effective_date <= v_as_of
    )
  order by oe.id desc limit 1),
```

**Semantics (the one judgment call).** `linkedEventId` is the wallet event of the **newest still-live**
`link`/`confirm` occurrence event. "Still live" mirrors `private.schedule_occurrence_settlement`
exactly: a link counts only when its wallet event is effective on/before the read's UTC `asOf`, and it
is dropped once an effective reversal of it exists. The W3A ask said "the latest `link`/`confirm`
row's `linked_event_id`"; reporting a link that a previous unlink already reversed would leave a dead
"Unlink payment" button (clicking it fails — `reverse_financial_event` refuses a second reversal), so
the field instead reports the id a successful Unlink can actually reverse. After unlinking the newest
payment the field falls back to the next live one; once nothing live remains it is null and the
affordance disappears (proved in the DB test §3). `currentEventId` is unchanged — `skip`/`reopen` still
use it as the expected head.

## 8. Remaining limitations / notes

- **The DTO field is optional.** `ScheduledOccurrenceRow.linkedEventId?: string | null` (not required)
  so the unowned shared fixture `src/test/in-memory-recurring-gateway.ts` — which hand-builds a full row
  and is outside the owned paths — stays assignable under `exactOptionalPropertyTypes`. Both DB reads and
  the gateway parser always emit it; `OccurrenceDetail` treats absent as null. If the coordinator prefers
  a required field, adding `linkedEventId: null` to `coreOccurrenceRowFixture` and tightening the type is
  a follow-up in their owned paths.
- **`linkedEventId` is the newest live link, not necessarily the oldest.** With partial payments the
  Unlink button targets the most recent still-live payment; repeatedly unlinking walks back through the
  links. Unlinking an arbitrary/older specific payment is out of scope.
- **Future-dated reversal edge.** "Live" mirrors `schedule_occurrence_settlement` (`rev.effective_date <=
  asOf`). A reversal dated after `asOf` (not produced by the UI, which uses UTC today) does not yet hide
  the link. Consistent with the settled figure the same row reports.
- **Unlink targets a link/confirm's wallet event only.** A `skip`/`reopen` head is still `currentEventId`
  and is unchanged (reversed via the occurrence action, not the wallets gateway).
- Not run (per instructions): the full `pnpm test:db`, Playwright e2e, any SQL against a hosted database,
  any push/deploy. `pnpm check:ui` was the gate; `pnpm check:ops` migration-manifest failure is expected
  and left to the coordinator.
