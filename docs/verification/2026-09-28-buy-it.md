# Buy it — one-step purchase on a goal (record + link + close)

**Date:** 2026-09-28. **Base:** `edbd830` (`main`). **Branch:** `ws/buy-it`.
**Audit:** `docs/verification/2026-09-25-linking-audit.md` §4 ("'Buy it' on a purchase goal: record the categorized expense, link it and close the goal").
**Closes:** `docs/decisions.md` 2379-2389 — linking a purchase no longer needs a pasted expense UUID.

## Delivered (UI only — no migration, no new RPC)

A guided **Buy it** action on an active purchase goal, in three steps over commands that already exist:

1. **Record** the categorized expense through the wallets command (`record_categorized_financial_event`) with a fixed, caller-owned request id.
2. **Link** it with the goals `link_goal_purchase`, reconciling the created event by request id instead of a pasted UUID.
3. **Close** the goal through the existing `revise_goal_plan` close path.

- `src/features/goals/buy-it.ts` — the gateway-agnostic orchestrator (`runBuyIt`, `buyItCommands`, `GoalBuyItEnvironment`). Every step uses a fixed `BuyItRequestIds` (record/link/close) reused across retries; an ambiguous transport result is reconciled first (request-id lookup / `find_planning_command` receipt) before any retry — so a retry or a timeout can never double-post the expense or double-link the purchase.
- `src/features/goals/goal-buy-it-dialog.tsx` — the form (amount, wallet, category, date capped to the server today) and the per-step result list (recorded / linked / closed), bilingual, with the same DialogShell conventions.
- `src/features/goals/goal-detail.tsx` — the "Buy it" action for `kind === 'purchase' && state === 'active'`.
- `src/features/goals/goals-page.tsx`, `src/features/control-room/routes.tsx` — wiring (read-only gateway/reference pass-through).
- Tests: `buy-it.test.ts` (11), `goal-buy-it-dialog` cases, plus `e2e/goal-buy-it.spec.ts`.

## Remaining limitations

- The e2e covers **desktop only** (the flow is a dialog; mobile layout is not
  asserted).
- A later step failing after the expense is posted leaves the money posted and says
  so ("The money is already posted, so it is not reversed…") rather than reversing.
- The close step reconstructs the goal's revise input from the detail snapshot; a
  concurrent edit between opening and submitting is refused by the existing stale-head
  guard rather than merged.
