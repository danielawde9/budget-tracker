# Task 12 — Goals gateway evidence

**Deliverable:** the typed application boundary for goals — DTOs, error
classification, a Supabase gateway over the 11 RPCs from task 10/11, and a
state-machine hook generalizing the allocation gateway's accepted/ambiguous/
retry pattern from 2 mutation kinds to 8 — per
`docs/superpowers/plans/future-planning/12-goals-gateway.md`. Layer:
gateway/hooks only. No SQL, no visible screen edit.

## Process

Read every exact field list from `11-goals-projections-db.md` (`goal_page`/
`goal_detail`/`goal_history_page`'s return shapes) and `10-goals-commands-db.md`
(all 8 mutation payloads) before writing `types.ts`, then reused
`planning-shared/rpc.ts`/`parse.ts` verbatim (task 07's own instruction:
"first implementation creates it, later gateways import it without copying
divergent [validation] logic") rather than re-deriving a transport or parser
primitives. One genuinely new primitive was needed and added to the shared
module rather than duplicated locally: `head`/`nullableHead`, validating the
64-lowercase-hex earmark/definition stale token task 10/11 introduced —
explicitly never conflated with a bigint revision counter, matching the
task's own "A 64-hex funding head is not a bigint definition revision"
instruction. All 239 tests (goals + planning-shared + allocation) passed on
the first real run — the parsing/gateway/hook design mirrored an
already-proven pattern (allocation's own gateway/hook) closely enough that
no defect surfaced needing a fix cycle.

Task 1's own text flags a cross-feature requirement: "G1 introduces
`publish_allocation_month_v2`: add an explicit v2 gateway method and typed
`goalTargets`, never ambiguously choose an overloaded RPC." Task 11's
`publish_allocation_month_v2` is fundamentally an allocation-month-publish
operation extended with goal integration, not a goals-domain operation
itself, so this extension necessarily touches `src/features/allocation/`
rather than `src/features/goals/` despite task 12's own "owned files" list
naming only the goals directory — the alternative (skipping this explicit
requirement because it falls outside the literal file list) would leave the
task incomplete. See `docs/decisions.md` for the resulting scope note.

## Task 1 — DTOs and the `GoalsGateway` method table

`types.ts` declares the exact 11 methods from the task's own table
(`loadPage`→`goal_page`, `loadDetail`→`goal_detail`, `loadHistory`→
`goal_history_page`, `create`→`create_goal_plan`, `revise`→`revise_goal_plan`,
`reserveOrRelease`→`record_goal_earmark`, `move`→`move_goal_earmark`,
`reverse`→`reverse_goal_earmark`, `linkPurchase`→`link_goal_purchase`,
`setMonthlyTarget`→`set_goal_monthly_target`, `setMilestone`→
`set_goal_milestone_state`, `findCommand`→`find_planning_command`) plus every
DTO the task's exact field lists declare — `coveredMinor`/`shortageMinor`
nullable independent of `earmarkedMinor`/`fulfilledMinor` (a goal with
unknown coverage is never coerced to zero), `earmarkHead`/`definitionHead`
kept as distinct opaque strings (never unified with `revisionId`'s bigint
shape). No generic arbitrary-RPC escape hatch is exposed — every method is
its own typed function calling exactly one RPC name.

## Task 2 — Validation and transport

Every response field goes through a boundary parser before the DTO is
trusted — no field is ever cast from the raw jsonb response. Proved: the
task's own monetary-fixture assertions (`coveredMinor: '10000'` →
`shortageMinor: '20000'` from a complete fixture), the
`9007199254740993`-preserved/equivalent-unsafe-number-rejected pair, a
malformed head token, an invalid leap `dueDate`, an unknown `state`/
`sourceKind` enum, a duplicate goal row, an incomplete two-part page cursor
and an incomplete three-part history cursor (both rejected client-side
before ever calling the transport, mirroring the SQL's own guard — "assert
at the right layer" applied on both sides of the boundary), and a
cross-space-shaped stale response (a `currency` value the DTO's own union
rejects). Every outgoing mutation argument is validated too — a malformed
`expectedHead`, `expectedFromHead`/`expectedToHead`, or purchase-line head
is rejected before the RPC call, not after a wasted round trip.

## Task 3 — Hook state machine

`useGoals` generalizes `useAllocation`'s exact accepted/ambiguous/retry
design across 8 mutation kinds (vs. allocation's 2) via one `RetryCommand`
union and a `runCommandByKind` dispatcher, rather than duplicating the
state-machine logic per mutation. Its "current view" is the first page of
`goal_page` for a given `(spaceId, currency, stateFilter)` — mirroring how
`useAllocation`'s view is one month's `allocation_month_state` — while
`loadDetail`/`loadHistory`/`loadMore` (pagination beyond the first page) are
stateless passthroughs, exactly matching `loadCategoryPage`/
`loadHistoryPage`/`loadTrend`'s own division of responsibility in the
allocation hook: the hook's state machine exists to coordinate mutations,
not to own every possible read. Proved: stale-response discard on a
space change, load-error recovery via refresh, membership-loss clearing,
double-submit rejection (never double-posted), accepted-refresh-pending on
a failed post-commit read (exactly one command call, never reposted),
ambiguous-then-identical-retry (same request id both attempts), ambiguous
resolved silently once a receipt is found, and a fresh command blocked
while ambiguous until explicitly cleared or reconciled — the identical
suite `use-allocation.test.tsx` already proved for `publishMonth`, now
proved once per generalized path plus once per the other 7 mutation kinds
reaching the gateway with their own freshly generated request id. The real
15-second-timeout-through-fake-timers combination is not re-driven here for
the same documented reason as task 07's own suite (a known jsdom/fake-timers/
React-scheduler memory hazard, not a defect) — the shared transport's own
timeout is proved once, in isolation, by `planning-shared/rpc.test.ts`.

## Cross-feature extension: `publishMonthV2`

`AllocationGateway.publishMonthV2` (typed `AllocationGoalTargetInput[]`) is
a distinct method calling `publish_allocation_month_v2`, never an overload
of `publishMonth` chosen by argument shape. `useAllocation`'s own
`RetryCommand` union gained a third kind (`publishMonthV2`) via the same
generalization applied to `useGoals`, reusing `runAllocationCommand`/
`ALLOCATION_COMMAND_NAME` instead of the two-armed ternary the file
previously used for its two commands. `unavailableAllocationGateway` in
`control-room/routes.tsx` needed the new method to keep satisfying the
`AllocationGateway` interface (a compile-time catch, not a test).
