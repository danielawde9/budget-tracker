# Task 07 — Allocation gateway evidence

**Deliverable:** the typed application boundary for allocation — shared
abortable RPC transport, explicit boundary parsers, DTOs, the Supabase
gateway, and a state-machine hook — per
`docs/superpowers/plans/future-planning/07-allocation-gateway.md`. Layer:
gateway/hooks only. No SQL, no visible screen edit.

## Process

Built test-first, file by file, in the task's own dependency order:

1. `src/features/planning-shared/rpc.ts` — the exact given `planningRpc`
   transport (15-second abortable wrapper around a PostgREST-shaped
   `RpcBuilder`). 8 tests: success/error passthrough, exact name/args
   forwarding, caller-signal abort (both live and pre-aborted), listener
   cleanup, and the 15-second timeout itself (fake timers, no React).
2. `src/features/planning-shared/parse.ts` — the four given base parsers
   (`object`, `minor`, `date`, `month`) plus the additional explicit parsers
   the DTOs need (`planningMoneyInput` for the SQL 15-digit mutation bound,
   `uuid`/`nullableUuid`, `bigIntId`/`nullableBigIntId`, `boolean`,
   `integer`/`nullableInteger`, `nullableSignedIntegerText` for
   `actualShareOfIncomeBps`, `currency`, `enumValue`, `array` with a length
   cap, `uniqueBy`). 52 tests including the task's exact monetary fixture
   (`plannedIncomeMinor: '200000'` → `incomeAfterSpendingMinor: '19000'`),
   the `9007199254740993` bigint-preservation/unsafe-number-rejection pair,
   and an invalid-leap-date rejection.
3. `src/features/allocation/money-allocation.ts` — the exact given
   `allocateIncome` implementation, ported verbatim (not re-derived). 14
   tests: the task's own A2.1 fixtures, cross-checked against the identical
   vectors `tests/db/allocation-commands.integration.test.ts` proved against
   the real SQL helper (200000 → 112000/48000/40000/residual 0; 101 →
   57/24/20/residual 0; 1 at 5000/3000/2000bps → 1/0/0/residual 0; 100 at
   5600bps → 56/residual 44), plus a bounded 0..1000 conservation sweep
   across six weight vectors (including a 12-group equal split) asserting
   both exact conservation and a <1-minor-unit deviation from each group's
   ideal share, and an explicit order/id tie-break case.
4. `src/features/allocation/types.ts` — DTOs copied from task 06's exact
   return-field list and task 05's exact mutation payload shapes.
5. `src/features/allocation/errors.ts` — classifies every SQLSTATE/message
   token from `01-sql-contract.md`'s error table plus every domain-specific
   `P0001` message `save_allocation_template`/`publish_allocation_month`
   raise (collected by grepping the actual migration files, not
   re-deriving from memory). 22 tests, including EN/AR copy substitution
   and the precedence rule that a transport-shaped (timeout/abort) failure
   classifies as `timeout` even if its message text also happens to contain
   a `planning_stale_revision`-shaped substring — the transaction outcome is
   unknown, so "timeout" must win over "definitely rejected."
6. `src/features/allocation/supabase-allocation-gateway.ts` — maps every
   `AllocationGateway` method to its RPC with the exact camelCase→p_snake_case
   argument mapping from the task's table, and validates every response
   field explicitly (no unchecked cast). 28 tests: exact arg mapping per
   method, AbortSignal forwarding, the complete monetary fixture, bigint
   preservation, unsafe-number/null-required-field/unknown-enum/duplicate-row
   rejections, the 14-row group cap (12 real + 2 synthetic) and the
   real-vs-synthetic identity rule (two synthetic rows with `groupId: null`
   are distinct by `rowKind`; a duplicate real `groupId` or duplicate
   synthetic `rowKind` is rejected), the 101-row category-page cap, and
   client-side pre-flight rejection of an over-cap group list or a negative
   mutation amount before any RPC call is made.
7. `src/test/in-memory-allocation-gateway.ts` — a test fake with the exact
   plan-pack Task 3 fixture (`coreMonthStateFixture`) and idempotent
   request-id-keyed receipts for `saveTemplate`/`publishMonth`.
8. `src/features/allocation/use-allocation.ts` — the six-state status union
   (`loading/ready/saving/accepted-refresh-pending/ambiguous/error`),
   AbortController-based read cancellation on space/month/currency change,
   and mutation reconciliation via `find_planning_command`. 11 tests (see
   below); one planned end-to-end test was written and then removed after
   it reproducibly crashed the test worker (see `docs/decisions.md`).

## Hook state-machine coverage

Proved: initial load to `ready`; a stale response from a space that is no
longer selected is discarded, never overwriting the current one (deferred
promises, mirroring `use-wallets.test.tsx`'s own stale-response test); a load
error surfaces and `refresh()` recovers; membership loss clears the space's
data and calls `onSpaceUnavailable`; a mutation posts with a generated
request id and refreshes to `ready`; a second command while one is `saving`
is rejected without a second RPC call (double-submit is impossible, not just
discouraged); a command that succeeds but whose follow-up read fails reaches
`accepted-refresh-pending`, and a later `refresh()` reaches `ready` **without
reposting the command** (`publishMonth` called exactly once, asserted
directly); a timeout-shaped mutation failure with no matching receipt reaches
`ambiguous`, and `retryAmbiguous()` reuses the **identical** request id (not
a fresh UUID) and succeeds; a timeout-shaped failure whose receipt **is**
already visible is treated as accepted without reposting; starting a fresh
command while `ambiguous` is rejected until `clearAmbiguous()` is called;
`loadCategoryPage`/`loadHistoryPage`/`loadTrend` fill in the current
space/month/currency automatically.
