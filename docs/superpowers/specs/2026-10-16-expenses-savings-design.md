# Expenses, savings and opening balances

Approved in chat on 2026-10-16; user explicitly requested implementation in this session.

Home shows monthly expense planned/spent/remaining, actual versus planned pace, spending by group and expense group progress. Remove the assignment hero, breakdown, plan links and savings tiles; retain actionable over-assignment warnings, bills, recent activity and wallets. Savings, investments, insurance and Mazoot are savings; essentials, guilt-free and short-term goals are expenses. Store an editable expense/savings purpose on each plan-version group, preserving earlier months. Never infer persisted behavior from display names after creation/backfill. Reserve items inside expense groups remain set aside and are excluded from monthly expense allowance. Short-term goals follow their expense group and are spendable; flex inside savings groups is savings.

Plan separates Expenses and Savings, offers group purpose editing, and clearly exposes Add opening balance on the page and each category. Category opening assigns existing Ready money with the existing opening flow; it never changes wallet cash, income or monthly funding. Accounts exposes Add opening balance for each existing account and at page level, plus labelled account actions replacing all three dots. Account opening records only previously unrecorded money, with amount/date and a preview of the addition; warn against entering money already in the account. Support cash, investment and loan opening semantics through existing immutable ledger constraints and idempotent commands. Both opening forms preserve currency and reject invalid/future dates and invalid amounts.

Activity shows category and group badges with visible server-side month, account, category, group, purpose and transaction-kind filters. These are existing category labels, not a new custom-tag subsystem. Filters apply before pagination and retain corrections. All UI is EN/AR, responsive and keyboard accessible. The user additionally requested consistent padding inside hover backgrounds across interactive rows and text actions; apply shared control styles without layout shifts. No data resets or automatic production publication.

Verification: real PostgreSQL tests for purpose roundtrip/history, old-client save preservation, opening conservation/idempotence/auth and filtering before pagination; UI tests for savings exclusion, opening forms and direct Accounts actions; complete UI/database suites, typecheck/build, and desktop/mobile browser checks.
